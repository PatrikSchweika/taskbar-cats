# Cat Play Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Two idle cats sometimes chase each other, play-fight (tussle) or groom.

**Architecture:** A play coordinator (`src/core/social.ts`, `Playground`) pairs up free cats and runs each game's clock and roles. `Cat` reads its role and steers by it, at the "play" place in its priority chain, with two new states (PLAY, GROOM). The colony drives the `Playground` each tick. No platform code changes apart from one settings row on each platform.

**Tech Stack:** TypeScript on Node 22 (`node --test` with native type stripping), GJS/St and libadwaita on GNOME, Electron 44 on Windows, Biome.

**Spec:** `docs/superpowers/specs/2026-11-16-playful-cats-design.md` (sections "What a cat does, in priority order", "Play", "New sprite frames", "Settings summary").

## Fitting in with the other three plans

Four plans implement the design: cat play (this one), [food bowls](2026-11-16-food-bowls.md), [name tags](2026-11-16-name-tags.md) and [petting](2026-11-16-petting.md). They can land in any order. They touch the same few places, so every plan follows these rules:

- **The priority chain.** `Cat.update` decides each tick with drive flags (`hunting`, `interested`, `sleepy` today) and one `if / else if` chain that sets `_target`. The design's full order is hunt → purr (`beingPetted`) → hover (`underPointer`) → food (`seekingFood`) → pointer interest (`interested`) → sleep (`sleepy`) → play → wander. Add your flag and branch at your place among the ones that exist. Your flag is false when any flag above it is true. Each existing flag below yours gets `&& !yourFlag`. Branches for new states in the state machine go right after the POUNCE branch, in the same order.
- **Shared building blocks.** Two pieces belong to two plans each: hover (name tags, petting) and the rub detector (petting, food bowls). Each plan that needs one carries the same task for it. If the code already exists, check it against that task's Interfaces block, run that task's tests, and move on.
- **Shared files.** New tests go in new `describe` blocks. New sprite poses, settings, settings rows and README lines go at the stated spot; leave entries from the other plans alone. If two plans are built on parallel branches, expect simple merge conflicts in `State`, `FRAME_RATE_SCALE`, `POSES`, the settings tables, the schema and the README. Keep both sides.

## Review Focus

1. **A cat removed from the settings mid-game.** Expected: the game ends for its partner, with no throw. Test: Task 3 "ends a game whose cat is gone".
2. **Play switched off mid-game.** Expected: every game ends at once. Test: Task 3 "ends every game when switched off".
3. **One cat, or many cats in a heap.** A lone cat never plays. With eight cats close together, no cat is ever in two games. Tests: Task 3 "a lone cat never plays" and "never puts a cat in two games".
4. **A fleeing cat at the screen edge.** Expected: it dashes past the chaser instead of pressing into the edge. Test: Task 3 "flees its chaser and dashes past when cornered at an edge".
5. **Anything more important happening mid-game** (a mouse, the pointer, sleepiness, and the drives from the other plans once they land). Expected: the game ends at once and both cats rest. Test: Task 3 "ends the game when either cat is interrupted, and rests both for 15 s".

### Task 3: Play: chase, tussle and groom

**Files:**
- Create: `src/core/social.ts`
- Modify: `src/core/cat.ts`, `src/core/colony.ts`
- Test: `tests/core/social.test.ts`, `tests/core/cat.test.ts`, `tests/core/colony.test.ts`

**Interfaces:**
- Consumes: the `play` and `groom` animations (Task 1). `Settings.social` (Task 2).
- Produces:
  - In `social.ts`:
    - `type GameKind = "chase" | "tussle" | "groom"`.
    - `interface PlayRole { kind: GameKind; partner: Cat; lead: boolean }`.
    - `interface Game { kind: GameKind; a: Cat; b: Cat; left: number; tagPause: number }`.
    - `PLAY_RATE = 0.04`, `PLAY_RANGE = 4`, `PLAY_REST = 15`, `TAG_REACH = 0.4`, `TAG_PAUSE = 1`.
    - `GAME_ODDS: Record<GameKind, number> = { chase: 0.4, tussle: 0.35, groom: 0.25 }`.
    - `GAME_SECONDS: Record<GameKind, [number, number]> = { chase: [4, 7], tussle: [2.5, 4], groom: [4, 6] }`.
    - `class Playground { readonly games: Game[]; update(dt: number, cats: readonly Cat[], enabled: boolean): void; clear(): void }`.
  - In `cat.ts`:
    - `State.PLAY = "play"` and `State.GROOM = "groom"`, with `FRAME_RATE_SCALE` 1.2 and 0.5.
    - `export const TUSSLE_REACH = 0.7, GROOM_GAP = 0.6, FLEE_SPEED = 0.8`.
    - `Cat.play: PlayRole | null` (set only by `Playground`).
    - `get interrupted(): boolean`: true when, on the last tick, any drive flag above play in the chain was true. Today that is `hunting || interested || sleepy`. It also includes `beingPetted`, `underPointer` and `seekingFood` from whichever other plans have landed.
    - `get free(): boolean`: `!interrupted && play === null`, with the state IDLE, SIT or WALK.
    - PLAY and GROOM count as `rooted`.

- [ ] **Step 3: Implement `Playground`**

Each update:
1. **End games** that are over: their time is up, either cat is `interrupted` or no longer in `cats`, or `enabled` is false. Set both cats' `play` to null and give both a rest timer of `PLAY_REST`.
2. **Chase tags:** when `tagPause <= 0` and the lead is within `TAG_REACH * lead.size` of the other cat, swap the `lead` flags and set `tagPause = TAG_PAUSE`.
3. **Count down** game clocks and rest timers. Drop the timers of cats that are gone.
4. **Maybe start** one game when `enabled`, consuming random numbers in the documented order.

`clear()` ends every game without starting rest timers.

- [ ] **Step 4: Implement play in `Cat.update`**

Play is the last drive before wandering. In the target chain it is an `else if (this.play)` branch right before the wander branch. No existing flag sits below it, so nothing else changes. `side` is `Math.sign(partner.x − x) || 1`.

- **Chase, lead:** target `partner.x`, at top speed.
- **Chase, follower:** target `x − side * 3 * size`, clamped to the roam range, at `FLEE_SPEED` of top speed. If the clamped target is within `ARRIVE_PX` of `x` (cornered), target `partner.x + side * 2 * size` instead.
- **Tussle:** each cat targets `partner.x − side * 0.55 * size`. Once within `TUSSLE_REACH * size`, switch to `PLAY`, facing the partner.
- **Groom, lead:** target `partner.x − side * GROOM_GAP * size`. On arrival, switch to `GROOM`, facing the partner.
- **Groom, follower:** target its own x. Hold `SIT`, facing the lead, while the lead is within `GROOM_GAP * size + ARRIVE_PX`. The `_sitFor` timeout must not end it.

**Separation:** skip `other === this.play?.partner`.

**Leaving play:** PLAY and GROOM drop to IDLE as soon as `play` is null or `interrupted` is true. Add them to the "no longer applies" list in the state machine.

**Bookkeeping:** record `interrupted` from this tick's flags before the state machine runs. Write it as one expression over every flag above play that exists, so a plan that lands later only has to add its flag there.

- [ ] **Step 5: Wire up `colony.ts`**

`Colony` owns a `Playground`. `this._playground.update(dt, this.cats, settings.social)` runs before the cats update, and `destroy()` calls `clear()`.
